Claude Multi-Agent Orchestration

프로젝트 운영 가이드

다중 에이전트 구조를 프로젝트에 적용하기 위한 표준 운영 문서입니다. 새 프로젝트 시작 시 Claude에게 이 문서를 먼저 읽히면, 에이전트들이 올바른 역할과 규칙을 이해하고 일관된 방식으로 협업합니다.

ver 1.0 내부 기술 문서 Claude Code 기반 Oracle DB 연동

00개요 및 목적

본 문서는 Claude 다중 에이전트 오케스트레이션 구조를 프로젝트에 적용하기 위한 표준 운영 가이드입니다. 이 구조의 핵심은 군대 지휘 체계로 비유할 수 있습니다.

COMMANDER
사령관
What을 결정합니다. 메인 미션 부여, 우선순위 결정, 최종 승인. 구현 복잡성은 에이전트에게 위임.
ORCHESTRATOR
중대장
How를 결정합니다. DAG 설계, 소대 할당, 진행 조율, 사령관 보고. 모든 소대를 지휘하는 메인 에이전트.
SUB-AGENT
소대장
서브미션을 수행합니다. 담당 폴더 안에서만 작업, 완료 시 중대장에게 보고, 실수 발생 시 LL 등록.

이 구조가 해결하는 문제

  • main.py 비대화 방지 — 역할별 폴더로 코드 분리, 모듈화
  • 맥락 분절 해결 — CLAUDE.md, HANDOFF.md로 세션 간 연속성 유지
  • 실수 반복 방지 — Lessons Learned 시스템으로 집단 학습
  • 병렬/순차 개발 자동 조율 — DAG 기반 의존성 관리
  • 사령관은 보고만 받으면 됨 — 구현 복잡성은 에이전트가 처리

01표준 프로젝트 폴더 구조

프로젝트 루트 아래에 아래와 같은 표준 구조를 따릅니다. 각 폴더는 하나의 에이전트(소대)가 전담합니다.

DIRECTORY TREE /my-project │ ├── CLAUDE.md ← [헌법] 루트 — 중대장 지휘 원칙 (300자 이내) ├── CURRENT_STATUS.md ← 현재 전체 진행 상태 ├── HANDOFF.md ← 세션 인계 사항 │ ├── /orchestrator ← 중대장 작업 공간 │ └── plan.md ← 현재 미션 DAG & 태스크 상태 │ ├── /engine1 ← 소대 A (예: DB 연결 / 데이터 수집) │ ├── CLAUDE.md ← engine1 전용 규칙 (300자 이내) │ └── *.py │ ├── /engine2 ← 소대 B (예: 데이터 처리 / 분석) │ ├── CLAUDE.md ← engine2 전용 규칙 (300자 이내) │ └── *.py │ ├── /gui ← 소대 C (화면 개발) │ ├── CLAUDE.md ← gui 전용 규칙 (300자 이내) │ └── *.py / *.html │ ├── /tests ← 통합 테스트 전담 │ └── *.py │ ├── /contracts ← 모듈 간 인터페이스 계약서 │ └── schema.py │ └── /memory ← 집단 학습 메모리 ├── LESSONS_LEARNED.md ← 전 에이전트 공유 실수/해결 이력 ├── KNOWN_ISSUES.md ← 알려진 문제 & 해결책 ├── PATTERNS.md ← 검증된 코드 패턴 └── /logs ├── orchestrator.md ├── engine1.md ├── engine2.md └── gui.md

02CLAUDE.md 계층형 구조 설계

⚡ 핵심 원칙
루트 CLAUDE.md = 헌법 (절대 불변, 모든 에이전트 준수)
하위 CLAUDE.md = 시행령 (모듈별 특화 규칙, 수시 업데이트 가능)
각 CLAUDE.md는 300자 이내로 제한 — 토큰 효율 극대화

에이전트 시작 시 읽는 순서

1
루트 CLAUDE.md 읽기 필수
전체 맥락, 절대 규칙, 역할 정의 파악
2
내 폴더 CLAUDE.md 읽기 필수
담당 모듈의 특화 규칙, 담당 테이블/API 파악
3
/memory/LESSONS_LEARNED.md 읽기 필수
과거 실수 파악 — 동일한 실수 반복 방지
4
/orchestrator/plan.md 읽기 필수
현재 미션 상태, 내 태스크 확인 후 작업 시작

루트 CLAUDE.md 템플릿

CLAUDE.md — 루트 # PROJECT: [프로젝트명] # ROLE: 이 문서를 읽는 너는 Orchestrator(중대장)이다. ## 프로젝트 목적 [한 줄 요약] ## 폴더 & 에이전트 역할 - /engine1 : [담당 업무] - /engine2 : [담당 업무] - /gui : 화면 개발 - /tests : 통합 테스트 전담 ## 절대 규칙 1. 에이전트는 자기 폴더 밖 파일 직접 수정 금지 2. 인터페이스 변경 시 반드시 /contracts/ 먼저 업데이트 3. 오류 발생 즉시 /memory/LESSONS_LEARNED.md 등록 4. 작업 시작 전 LESSONS_LEARNED.md 반드시 읽기 ## 소대 보고 원칙 1. 서브미션 완료 → plan.md 상태 업데이트 2. 블로킹 발생 → 즉시 중대장에게 보고 3. 새 패턴 발견 → /memory/PATTERNS.md 추가 ## Gate 조건 - GUI 시작: /contracts/ 파일 확정 후에만 - 통합 테스트: 모든 소대 완료 후에만 ## 기술 스택 - Python 3.11 / Oracle DB / [기타]

하위 CLAUDE.md 템플릿 (300자 이내)

engine1/CLAUDE.md # AGENT: engine1 # ROLE: DB 연결 및 데이터 수집 # SCOPE: /engine1 폴더만 수정 가능 ## 담당 - Oracle 연결 관리 (connectors/) - SELECT 쿼리 실행 - /contracts/schema.py 기준 출력 ## 금지 - 타 폴더 직접 수정 - contracts 미확정 상태에서 인터페이스 임의 변경 ## 참조 - 루트 CLAUDE.md 규칙 준수 - 작업 전 LESSONS_LEARNED.md 확인

03핵심 운영 파일 상세

CURRENT_STATUS.md

전체 프로젝트의 현재 상태를 한눈에 보여주는 파일. 사령관이 빠르게 현황을 파악하는 용도.

CURRENT_STATUS.md # CURRENT STATUS ## 최종 업데이트: YYYY-MM-DD HH:MM ## 메인 미션 [ ] M-001: [미션명] — 진행중 78% [x] M-002: [미션명] — 완료 ## 소대 상태 | 소대 | 담당 태스크 | 상태 | |----------|---------------|---------| | engine1 | DB 연결 모듈 | 완료 ✅ | | engine2 | 쿼리 최적화 | 진행중 | | gui | 조회 화면 | 대기 ⏸ | ## 현재 블로킹 - 없음 / [있다면 내용] ## 다음 마일스톤 - engine2 완료 후 GUI 시작 (Gate 조건 충족 예정)

HANDOFF.md

세션이 끊길 때마다 업데이트하는 인계 파일. 어떤 환경(Claude.ai / VS Code / Antigravity)에서 열어도 이 파일을 읽으면 바로 이어받을 수 있다.

HANDOFF.md # HANDOFF — 세션 인계 사항 ## 작성: YYYY-MM-DD HH:MM | 작성자: [에이전트명] ## 완료된 것 - [완료 항목 1] - [완료 항목 2] ## 현재 진행 중 (미완성) - 파일: /engine2/detector.py 58번 줄부터 - 이유: [중단 이유] ## 다음에 할 일 (우선순위 순) 1. [최우선 작업] 2. [두 번째 작업] ## 주의사항 / 알아야 할 것 - [중요 컨텍스트] ## 열려있는 질문 (사령관 결정 필요) - [사령관 판단이 필요한 사항]

orchestrator/plan.md

중대장이 작성하고 관리하는 작전 계획서. DAG 구조와 태스크 상태를 포함한다.

orchestrator/plan.md # MISSION PLAN: [미션명] ## 수립일: YYYY-MM-DD ## DAG (의존성 그래프) engine1(수집) ──┐ ├──→ contracts 확정 ──→ gui ──→ test engine2(처리) ──┘ ## 태스크 현황 | ID | 태스크명 | 담당 | 선행조건 | 상태 | |------|----------------|---------|----------------|---------| | T-01 | DB 연결 모듈 | engine1 | - | ✅ 완료 | | T-02 | 처리 알고리즘 | engine2 | - | 🔄 진행 | | T-03 | Interface 정의 | orch | T-01, T-02 | ⏸ 대기 | | T-04 | GUI 화면 | gui | T-03 | ⏸ 대기 | | T-05 | 통합 테스트 | tests | T-04 | ⏸ 대기 | ## 완료 조건 - 통합 테스트 100% 통과 - 사령관 최종 검토 승인

04집단 학습 메모리 시스템

에이전트들이 실수를 기록하고, 다른 에이전트들이 동일한 실수를 반복하지 않도록 하는 집단 학습 구조. 프로젝트가 진행될수록 에이전트들이 점점 스마트해진다.

실수 전파 프로세스

1
발생
소대가 오류 발견 및 해결
2
로컬 기록
/memory/logs/{agent}.md 에 즉시 기록

전체 등록

4

5
강화

Memory Protocol — 모든 에이전트 필수 준수

  • 🔵 작업 시작 전: LESSONS_LEARNED.md + KNOWN_ISSUES.md 반드시 읽기
  • 🔴 오류 발생 시: 즉시 logs/{agent}.md 기록 → 해결 후 LESSONS_LEARNED 등록
  • 🟢 작업 완료 시: plan.md 상태 업데이트 + 새 패턴 발견 시 PATTERNS.md 추가
  • 🟡 중대장 추가 책임: 실패 원인 분석 + retrospective 작성

05오케스트레이션 — DAG & 의존성 관리

두 가지 작업 유형

유형조건예시
병렬 Parallel다른 모듈의 output을 input으로 쓰지 않을 때engine1 수집 & engine2 알고리즘 동시 개발
순차 Sequential선행 태스크 완료 후에만 시작 가능contracts 확정 후에야 GUI 시작

DAG 예시

engine1 (수집) ──┐ ├──→ contracts 확정 ──→ gui ──→ 통합 테스트 engine2 (처리) ──┘

Interface Contract (핵심)

소대들이 독립적으로 동시 개발하려면 데이터 형식을 미리 합의해야 한다. 중대장이 /contracts/ 파일을 먼저 작성하고, 각 소대는 이 계약서를 기준으로 개발한다.

contracts/schema.py # 중대장이 작성 — 모든 에이전트가 이 형식 준수 DATA_SCHEMA = { "record_id": str, "value": float, # 단위: 명시 "status": str, # "normal" | "warning" | "critical" "timestamp": str, # ISO 8601 형식 } # engine1: 이 형식으로 출력 # gui : 이 형식으로 수신 가정하고 화면 개발 # → 둘이 동시에 개발 가능!

Gate 조건 — 절대 준수

🚫 GUI 에이전트는 /contracts/ 파일 없으면 시작 금지 HARD GATE
🚫 통합 테스트는 모든 소대 완료 후에만 실행 HARD GATE
🚫 Interface 변경 시 반드시 중대장 승인 후 진행 HARD GATE
✅ contracts 확정 이후에는 engine1 + gui 동시 개발 허용 PARALLEL OK

미션 전달 표준 형식

사령관이 이 형식으로 전달하면 중대장이 바로 DAG를 그릴 수 있다.

MISSION TEMPLATE 미션: [한 줄 요약] 목표: [완료 조건 — 테스트 기준 포함] 제약: [하면 안 되는 것, 반드시 지켜야 할 것] 우선순위: [속도 / 완성도 / 안정성 중 무엇이 중요한지] 참고: [관련 파일, 기존 코드, 참조할 계약서]

사령관이 직접 결정해야 할 것

  • 폴더 구조 — 어떤 모듈로 쪼갤 것인가
  • 기술 스택 — Python 버전, DB, GUI 프레임워크
  • 배포 환경 — 사내 서버? VPS? 로컬?
  • 접근 권한 정책 — SSO 연동, 권한 레벨 정의
  • 우선순위 — 속도 vs 안정성 vs 완성도

07세션 연속성 관리

Claude.ai / VS Code 익스텐션 / Antigravity 등 여러 환경에서 Claude를 사용할 때, 각 세션은 독립적으로 시작된다. 파일을 공유함으로써 맥락을 이어받는다.

💡 핵심 원칙: Claude가 기억을 못해도 파일은 어디서나 읽을 수 있다.
새 세션 시작할 때 "CLAUDE.md, HANDOFF.md 읽어" 한 마디만 해도 이어받기 가능.

세션 시작 시 필수 4단계

  1. 루트 CLAUDE.md 읽기 — 전체 맥락 파악
  2. HANDOFF.md 읽기 — 이전 세션에서 어디까지 했는지
  3. /memory/LESSONS_LEARNED.md 읽기 — 과거 실수 파악
  4. /orchestrator/plan.md 읽기 — 현재 미션 상태

세션 종료 시 필수 2단계

  1. HANDOFF.md 업데이트 — 완료한 것, 진행 중인 것, 다음 할 일
  2. CURRENT_STATUS.md 업데이트 — 전체 진행 상태 반영

08사령관 보고 체계

사령관이 개입하는 시점

구분내용
개입 불필요 ✅ 소대 간 버그 해결, 의존성 순서 조율, 실수 → LL 등록, 테스트 통과/실패 처리
개입 필요 ⚡ 요구사항 변경, 우선순위 결정, 비즈니스 판단, 방향성 질문

표준 보고 형식
